📌 课件使用

本课程要求你读懂课堂分析，复现主要结果，再检验自己的小改动。在线讲义用于阅读，GitHub 仓库提供源文件、代码和冻结数据。

第一次课可以直接阅读研究流程。后续每次课前都应准备好本地课件：首次克隆，以后更新，不用反复建立同一仓库。

先分开两个目录

教师课件与个人作业分开保存
  • 教师课件副本 FinEco：跟随教师更新，用来阅读和复现基准。不要把唯一一份作业保存在这里。
  • 个人仓库 fineco-homework：保存整个学期的研究计划、实验、作业和网站。与 FinEco 平级，不能放在它的内部。

教师课件强制更新时可能覆盖本地修改。个人仓库不执行这种强制对齐操作；作业提交和推送都指向你自己的仓库。

选择一种获取方式

下面 A、B 二选一，完成其中一条即可。不需要先用 Desktop 克隆，再让 Agent 克隆第二遍。尚未建立个人仓库时，先建立独立的个人练习目录，之后再将它纳入自己的 Git 仓库。

A. GitHub Desktop

适合希望通过图形界面操作的同学。推荐使用 GitHub Desktop 持续同步，不建议整个学期依赖手动 ZIP 下载。

  1. 在 GitHub Desktop 中选择 File → Clone repository → URL，输入 https://github.com/lianxhcn/FinEco.git。
  2. 选择学习目录，克隆为 FinEco。已有同名仓库时先检查它，不覆盖原目录。
  3. 在 VS Code 中打开含 README.md 和 data 的项目根目录，按软件配置检查内核与依赖。
  4. 使用冻结数据，重启内核后顺序运行第一讲 Notebook，按下方清单核对结果。
  5. 以后每次课前按同步步骤更新；作业和扩展实验保存到个人仓库。

Download ZIP 仅作临时备用。它没有 Git 历史，不能直接拉取更新；以后使用 Desktop 或 Agent 克隆时，应保留原有练习，避免直接覆盖。操作参考 GitHub Desktop 官方说明。

B. Agent，推荐

把下面的路径占位符换成自己的目录，再交给 Agent。已有仓库时让它更新，不能把“获取资料”理解成每次重新克隆。

提示词：准备课件并验收

我正在学习 FinEco，仓库为 https://github.com/lianxhcn/FinEco。教师课件目录是「填写路径」，个人作业目录是「填写另一个平级路径」。请按以下顺序执行：

  1. 检查两个目录，确认互不包含。教师课件目录已有仓库时报告远程地址、分支、提交版本和本地改动，再正常同步；没有仓库时使用 Git 克隆。缺少 Git 时说明安装步骤，不擅自修改全局环境。
  2. 阅读 README、AGENTS、RULES、requirements.txt 和软件配置页。说明讲义、数据、Notebook 与输出的位置，记录所用提交版本。
  3. 检查实际 Python、Stata 和内核路径。先跑最小示例，再从头运行第一讲 Notebook；使用冻结数据，不重新抓行情。无法运行 Stata 时如实记录，先完成 Python。
  4. 保留真实输出与错误，核对基准结果。把个人实验放进独立作业目录，维护数据相对路径，不把作业推送到教师仓库。
  5. 汇报运行文件、环境、结果、失败步骤和下一步。遇到本地修改或同步冲突，先检查和备份，不能直接强制覆盖。

完成后请亲自确认：当前内核是什么、数据来自哪个文件、结果保存在哪里。Agent 可以帮助操作，这三项仍需要你自己说清楚。

从复现到自己的小实验

先跑通未改动的案例，是为了建立可以比较的起点。如果一开始就同时换股票、改时间窗口和换模型，结果变化后就很难判断原因。

基准复现的验收清单
  • 重启内核后能顺序运行，代码单元格没有错误输出。
  • Python 实验能读入 10 只股票，报告缺失情况，并生成权重表和训练、验证、测试结果。
  • Stata 实验生成 800 家企业、10 年的模拟面板，手算 DID 与交乘项回归一致，固定效应估计接近已写入的 -0.4 个百分点。
  • 使用相同数据和版本时，关键结果应一致或只有可解释的数值舍入差异；图片文件名和执行日期可以不同。

接下来做一项受控改动：

  1. 保留基准：在个人作业仓库中创建保留数据相对路径的练习副本。已有 Python 内核可以继续选用，不必再次安装系统软件。
  2. 先作预测：只选择一个条件。例如，提高交易成本后，同一配置的净收益应怎样变化？
  3. 运行并比较：在练习副本中修改，从头运行。分别保存基准与修改后结果，注明改变了什么。
  4. 解释差异：写出观察到的变化、与预测是否一致、尚不能回答的问题。不要因为结果不合预期就删掉它。

股票实验提供交易成本比较；政策实验提供已知效应大小的修改。完成后再考虑更有挑战的假设变化。具体步骤见两个实验页的末尾；这些拓展是课后练习，不改变一页研究计划的提交要求。

可以继续给 Agent 以下指令：

请保留课程基准文件，在独立练习项目中只改变我指定的一个条件，其他数据、参数和随机种子保持一致。先解释预期影响，再修改并运行。记录修改位置，生成前后结果对照，解释差异。不要修改其他课程目录，不向课程仓库推送我的练习结果。

发现问题怎样反馈

读不懂一个符号、发现链接失效、同样数据无法复现，都是有价值的反馈。Issue 是仓库中的公开问题记录，方便教师追踪、讨论并在修订后告知大家。

  1. 打开 已有 Issues，先看是否已有相同问题。
  2. 登录 GitHub，点击 New issue，用“页面或文件 + 具体问题”写标题。
  3. 按下面清单描述情况，检查内容后提交。操作可参考 GitHub Issue 说明。
问题类型：文字/公式/链接/代码/结果解释
页面链接与小节，或 Notebook 文件与单元格：

我做了哪些操作：
我预期看到什么：
实际看到什么 (保留必要错误信息)：
相关环境版本 (仅代码问题需要)：
我的理解或建议：

文字问题不必填写软件环境；代码问题尽量提供能重复出现问题的最小步骤。截图或日志中隐去个人路径、账号和凭据，不上传受限数据。可以让 Agent 帮你整理 Issue 草稿，由你核对后提交。

文件放在哪里

目录或文件 学习时的用途
lectures/ 理论讲义源文件，网页中的公式和解释来自这里
notebooks/intro/ 第一讲代码及已保存的输出
data/intro/ 冻结行情、来源清单和案例结果表
exercises/ 作业要求
settings.qmd、requirements.txt 环境说明和依赖版本
tools/ 取数、批量执行与构建工具；常规复现不必重新取数
docs/ 发布网站的生成文件；学生运行案例不用修改这里

第一次练习做到“下载完整材料—环境验收—复现一个案例—解释一个改动”即可。无需先掌握网站构建或所有 Git 操作。
