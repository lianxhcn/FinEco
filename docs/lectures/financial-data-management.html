3  金融数据管理：从多张表到分析底表

下载完成后，目录里可能同时出现个股日行情、市场指数、宏观月度指标、年度财务表和公司信息。单独打开任何一个文件都不困难；困难在于下周换一个研究问题时，能否再次准确地找到、连接并解释这些数据。

本章以《数据分析与经济决策》课程的数据管理讲义为主体，保留多表场景、主键与粒度、存储格式、SQL 查询和工作流，结合《金融数据分析》的数据契约和目录规范展开。分析工具仍可以是 pandas；在它的上游，我们需要先理清数据如何组织。

本讲要点

建立粒度、主键和复用意识；能解释 append、merge、reshape 和聚合的区别；能选择文件或数据库保存方式，并把处理过程写成别人可以重跑的工作流。完整教学代码见 Notebook 的小表实验，真实项目见 CSMAR 合并阶段。

3.1 一个金融研究中的多表场景

设想我们要比较某年不同企业的资产规模和交易活跃程度。资产来自年度财务表，换手率来自日行情，公司名称来自身份表。目标是每个公司每年一行，因此所有数据最终必须与这个单位相容。

数据表 每行代表什么 候选键 在年度研究中的用途
日行情 某证券某交易日 证券代码、日期 先形成年度交易特征
指数日行情 某指数某交易日 指数代码、日期 市场表现或共同时间信息
宏观月表 某指标某地区某月 指标、地区、月份 明确聚合及可得时间后连接
年度财务表 某公司某年某报表口径 公司标识、年度、报表类型 保留所需财务口径
身份历史表 某标识在某有效期间对应的对象 标识、有效起始时间 处理名称、代码或上市状态变化

来源讲义用公司静态表、年度表和日表解释这一过程。静态公司表是有意简化：真实行业、所有权、简称和证券代码可能变化，不能把当前值无条件倒填过去。证券代码与公司 ID 也不是天然一一对应。

图中 company_info 视作静态表，适合说明连接关系；真实研究需另行验证有效时间。code 是技术连接键的示意，不等于已经解决了公司身份问题。底表行数正常，也仍可能连接到错误时期的属性。

3.2 主键与粒度：先说明一行代表什么

主键是能唯一识别一行的变量或组合；粒度是每行对应的经济对象与时间层级。键可以帮助检查粒度，却不能凭空定义粒度。给每行生成不同的流水号，当然能够唯一，但不能证明一行就是一个公司年度。

设候选键为 \(K\)，总行数为 \(N\)，不同键值组合的数量为 \(U(K)\)。必要的键检查为：

\[ U(K)=N,\qquad \text{Missing}(K)=0. \]

第二个条件要求键中没有缺失。即使所有缺失组合只出现一次，仍然没有足够身份信息完成可靠连接。发现重复时，要查看它对应不同报表、不同期间、多个证券、修订版本，还是重复导出，不能直接删除重复键。

3.2.1 用三张小表建立直觉

下面全部为虚构教学数据，金额单位任意但一致，换手率以百分数记录。

firm year assets
A 2020 100
B 2020 200
firm date turnover
A 2020-01-02 1
A 2020-01-03 3
B 2020-01-02 2

公司表另有 A、B 两行及其虚构行业。年度表的键是 (firm, year)，日表的键是 (firm, date)，公司表在这个简化例子中的键是 firm。先写出这些关系，再决定操作；变量恰好同名不能替代经济判断。

3.2.2 错误合并为什么可能不报错

把两张表直接按公司和年份连接，A 的资产 100 会被复制到两天，B 的资产保留一次，于是年度表从 2 行变为 3 行。代码可以正常完成，但它改变了观测权重：A 在后续不加说明的逐行计算中出现两次。

图中 ret_mean 代表期间内平均日收益，不能将其误称实际年度持有回报。此处的可运行小表改用平均换手率，使学生先集中理解粒度。A 的平均换手率为 (1+3)/2=2，B 为 2。聚合后每公司每年一行，与年度表连接后仍为 2 行。

同一个连接在另一种目标下可能合理：若研究日收益与已公开财务特征的关系，日表可以作为母表，将当时可得的财务信息广播到后续交易日。此时目标本来就是证券日度，验收应检查日度键和信息可得时点，而不是强制保留年度行数。

3.3 追加、合并、变形和聚合

这些操作都能把文件变成一个表，但改变的对象不同。学生如果只要求 Agent 合并所有数据，实际上尚未给出可执行的数据设计。

3.3.1 Append：增加同类记录

追加把相同含义的列纵向排列，例如将按年份分开的行情文件连接起来。追加前核对列名、类型、单位和覆盖时期，追加后检查总行数、来源标签与重复键。

若一个文件止于 2020 年底，另一个从 2020 年开始，两者有重叠期，行数相加正确仍可能重复。应保留文件来源列，将重叠记录交给规则判断。本章 CSMAR 股东表有两个导出分片，Notebook 第 02 节实际检查了拼接后的完整键。

3.3.2 Merge：沿键增加信息

合并前先判断关系：一对一表示双方键均唯一；多对一表示母表可多行对应同一条右表信息；一对多则会使左侧信息重复。多对多可能是业务事实，但必须先解释预期组合数，不能作为默认连接方式。

连接方式 保留哪些键 需要追查什么
left 左表全部键及其匹配 右侧未匹配为什么出现
inner 两侧共同键 谁被丢弃，是否改变目标总体
outer 两侧键的并集 仅左、仅右和共同观测各有多少

下面接续 Notebook 第 04 节已生成的 views，按已识别的 A 口径建立两侧年度视图。代码在该节有对应执行单元；读者可 clone 仓库、取得授权数据后从第 00 节顺序运行，不应单独执行一个尚未定义 views 的片段。

# A/B 保留在年度视图中；本次只连接 A 口径，未销毁 B 记录。
left = views["balance"].query("Typrep == 'A'")
right = views["income"].query("Typrep == 'A'")
keys = ["stock_code", "fiscal_year"]
require_key(left, keys, "资产负债表 A")
require_key(right, keys, "利润表 A")
merged = left.merge(
    right, on=keys, how="outer",
    validate="one_to_one", indicator=True,
    suffixes=("_balance", "_income")
)

validate 使非预期重复直接失败，indicator 留下匹配状态。它们解决结构核验的一部分，不能确认字段单位或证券身份是否正确。两个季度表误用年度键，或者两表都只剩一个错误版本，也可能在技术层面通过唯一性检查。

3.3.3 Reshape：同一信息换一种排列

宽表可能把 assets_2019 与 assets_2020 放在不同列；长表用 year 列保存年份，用 assets 列保存数值。改成长表后，年份更容易筛选、滞后和连接。melt 常用于宽转长，pivot 用于长转宽，但后者要求指定的行列组合唯一。

不要为了让 pivot 成功就改用默认取均值的 pivot_table，那会把变形悄悄变成聚合。若一家公司同年有两种报表，应该保留报表类型维度或明确选择规则。教学小表中的宽长往返检查会验证数值和键是否保持。

3.3.4 Aggregate：为目标粒度定义统计量

日度换手率可以计算均值，年度营业收入通常按年度报告口径取得；季度累计收入不能随意相加得到全年收入。聚合算子必须对应变量含义。

日简单收益率 \(r_{id}\) 使用小数表示，\(d\) 为期间内交易日。若数据完整、公司行为口径一致且没有额外现金流处理问题，期间复合收益为：

\[ R_{it}=\prod_{d\in\mathcal D_{it}}(1+r_{id})-1. \]

\(\mathcal D_{it}\) 为证券 \(i\) 在期间 \(t\) 纳入计算的交易日集合。平均日收益乘交易日数是另一种近似或年化均值指标，不能替代这个实际期间复合收益。教学数值 +10% 和 −10% 的两日回报为 −1%，算术均值为 0，直观体现了差别。

日收益波动率通常以日收益的标准差表示，年化还需要假定与约定。不能用平均绝对收益直接冒充标准差，也不能不检查缺失交易日便宣称计算了完整年度风险。完整金融模型将在后续章节展开，这里先把字段名称写准确。

3.4 存储格式也是数据契约

《金融数据分析》课程提出的数据契约意识很有用：接收方除了得到一个文件，还要知道它承诺了怎样的结构。格式保存部分技术信息，数据字典保存经济含义，两者必须配合。

格式 适合什么工作 需要额外注意
CSV 分享、小表、人工检查、跨工具交换 不保存可靠的字段类型契约，明确编码与读入规则
Excel 人工录入、多个工作表和报告展示 表头、格式、公式与实际数值分开核对
Parquet 标准化中间表、反复分析和选择列 保存类型仍不等于保存全部经济定义
SQLite 本地多表关系、SQL 查询和约束 表结构、索引和约束需要明确建立
DuckDB 面向本地文件的分析查询 结果仍受原数据粒度和类型限制

CSV 接近逐行排列的文本，Parquet 按列组织并保存 schema，因此选择少数列、压缩相似数值和重复分析时常有优势。不过，压缩比和读取速度取决于数据、列数、压缩方式和缓存。不能把某一份课程示例的性能倍数当普遍结果，也不需要设定一个固定文件大小作为唯一切换阈值。

3.4.1 类型、编码与经济定义

用引号包住 CSV 中的 000001 不保证所有读取器都将其保留为字符串，应在读取时明确类型。Parquet 可以保存字符串、日期等类型，但若转换前类型已经错了，它也会忠实保存错误。将 roe 保存为浮点数并不能告诉别人 5 表示 5% 还是 500%。

数据字典至少记录变量名、含义、原始字段、类型、单位、缺失编码、报告口径、有效期间和构造公式。代码中的映射与字典保持一致；来源说明没有单位时写待确认，不根据常识补上人民币元。

3.4.2 读取时只取需要的信息

读取 Parquet 时可以指定需要的列；查询引擎还能结合文件统计信息与分区跳过部分数据。这样减少不必要的读入和内存使用。CSV 的 usecols 可以减少保留的列和内存占用，但仍要解析文本结构，不能与列式文件的物理读取机制完全等同。

若按年份保存多个分区，需保证各分区使用一致的 schema，新增年份时记录字段变动。分区不等于样本筛选：2014 年支持数据虽然不属于研究期，仍可能用于 2015 年平均资产分母，应保留可追溯关系。

3.5 SQLite 与 SQL：把多张表放在一起

来源讲义用 SQLite 演示从多文件到统一查询的过渡。SQLite 数据库可以是一个本地文件，Python 的 sqlite3 模块提供访问接口；也可用内存数据库演示，不需要部署数据库服务器。建库不是必经步骤，反复查询和多表协作时才体现价值。

3.5.1 从表结构到查询结果

基本流程是先定义表结构与约束，再导入数据，检查行数、期间和键，之后用 SQL 筛选或连接，将结果读回 pandas。DataFrame.to_sql() 提供方便的写表方法，但不会自动理解哪个组合应为业务主键。需要约束时应明确建表，或先核验再建立唯一索引。

在教学小表实验中，公司和年度表写入内存数据库，(firm, year) 建立唯一索引，然后执行下面的查询。

SELECT c.industry, COUNT(*) AS n, AVG(f.assets) AS mean_assets
FROM annual AS f
JOIN company AS c ON f.firm = c.firm
WHERE f.year = 2020
GROUP BY c.industry
ORDER BY c.industry;

FROM 选母表，JOIN 添加行业信息，WHERE 限制年度，GROUP BY 按行业分组，COUNT 和 AVG 返回组内数量与平均资产。结果与同一小表的 pandas 实现进行比较。两种软件得到同样结果是一项实现检查，仍需确认两者没有使用同一种错误定义。

目的 pandas 思路 SQL 表达
选列 指定列列表 SELECT
筛选 布尔条件 WHERE
排序与取前几行 sort_values、head ORDER BY、LIMIT
分组汇总 groupby GROUP BY 与聚合函数
连接关系表 merge JOIN ... ON ...
检查重复组合 duplicated GROUP BY ... HAVING COUNT(*) > 1

SQL 聚合也要关注缺失：COUNT(*) 统计行，COUNT(assets) 统计该字段非空值，AVG(assets) 忽略 NULL。报告平均数时同时报告有效样本量，避免不同指标的均值来自不同人群却被当作共同样本比较。

3.5.2 四类实际查询怎样设定

年度交易概览。 先按证券和年份计算观测交易日数、平均换手率与收益统计，再连接年度属性。每个指标写清小数或百分数、是否年化、缺失日处理。不能将一个带百分号的平均值重复乘 100。

异常成交日。 可以将某日成交量与同年均值比较，找出值得检查的观测。但全年均值含未来交易日，因此适合事后描述；若用于当时的交易信号，应换成截至当日之前可得的基准。

日行情与月度指标。 提取月份后连接月表，可以把同一月值重复到多天。它解决频率匹配，不解决信息可得性。若月统计值在次月发布，当月交易决策不能使用它，应根据发布日期作可得信息连接。

日行情与财务表。 若目标为年度研究，先聚合行情再连接；若目标为日度预测，使用已公告且在有效期间内的财务记录。不能用字符串年份相同作为唯一经济依据。

这些查询保留了来源讲义的应用场景，并将结构关系、指标定义和信息时间一起纳入验收。学生应先用很小的数据验证，再处理整批文件。

3.5.3 建立可重跑的文件数据库

从多个 CSV 建库时，应显式列出输入文件和字段映射，不能靠文件行数推断公司信息表是长表还是宽表。不同 schema 分别处理，缺少必须字段时报告，而不是跳过后继续给出完成结论。

生成数据库写入派生目录，保留原始 CSV。每次运行可以写入新版本数据库，核验完成后再由规则决定是否替换使用入口。if_exists='replace' 会替换指定表，适合明确的重建任务，不能在未知已有成果上随意使用。写入完成还要检查读取后的类型、行数和查询结果，而不只看文件存在。

3.6 DuckDB 与 Parquet：查询本地大文件

当资料分布在多个 Parquet 文件，且任务主要是筛选、分组和连接时，可以考虑 DuckDB。它提供对 Parquet 等文件的分析查询，不必先把全部记录加载到 pandas。具体接口见 DuckDB 官方 Parquet 文档。本章介绍使用位置，不要求学生为完成 CSMAR 案例安装新的数据库系统。

选择工具时先问瓶颈在哪里。如果只是几张小表，pandas 已足够；如果相同关系表要反复查询，SQLite 可以集中管理；如果任务是在大量本地列式文件中筛选聚合，DuckDB 提供另一种路线。把所有数据换个后缀或导入数据库，并不会自动使错误合并变正确。

性能比较应使用相同输入、列、筛选条件和聚合定义，先比较结果是否一致，再讨论时间。首次读取与缓存读取、是否包含建库时间、是否只取需要列都会影响比较。这里不沿用来源讲义的机器计时，也不把工具排序当成研究结论。

在多人机构环境中还会遇到服务器数据库、权限控制和任务调度。它们扩大了数据规模和协作方式，但主键、schema、来源追踪和验收规则仍然适用。理解本章的小表比背诵更多产品名更有迁移价值。

3.7 目录、命名、字典与交接

数据项目长期可维护，依赖于别人能否在没有原作者口头解释时找到输入与运行入口。目录和文档要服务于这个目标。

3.7.1 按数据生命周期分层

project/
  README.md                 项目目的、环境、运行顺序
  AGENTS.md                 Agent 工作边界
  DATA_PROTOCOL.md          数据定义与验收规则
  data/raw/                 获得的原始文件，只读
  data/interim/             标准化表、可重建数据库
  data/processed/           候选底表与研究版本
  notebooks/                教学解释、代码与保存的输出
  tools/                    可复用处理脚本
  audit/                    来源清单、样本流、匹配和分布
  decisions.md              已确认决定与待裁定事项

这是独立学生项目的通用示意。FinEco 中受限 raw/interim/processed 位于授权数据根，公开 data/financial-data/ 只放说明与汇总，详见运行说明。不要为了符合示意目录而移动教师原始资料。

原始数据、标准化表和研究样本承担不同责任。标准化可以更正字段类型与确认后的单位，但不默认删除金融行业；研究样本可以执行论文规则，但须保留从基础库重建的路径。规则改变时生成新研究版本，不反向改掉原始输入。

3.7.2 文件名要能排序和辨认

使用主题、范围和版本，例如 financial_annual_2014_2025_v1.parquet。日期采用可排序格式，版本写清顺序。避免只有“最终版”“老师改过的”等依赖记忆的名称。已有数据库导出文件保留原名，通过 manifest 建立规范数据集名称，不为美观而修改原始文件。

相同文件名可能有不同内容，因此记录 SHA256。哈希相同支持字节未变，不能证明来源内容本身正确；文件重新编码后哈希不同，也不必然意味着经济数值变了。应结合 schema、覆盖和变量比较判断。

3.7.3 数据字典与 README 各写什么

字典围绕字段，README 围绕项目。字典解释 total_assets 来自哪个源字段、使用什么金额单位、属于什么报表；README 说明数据从哪里获得、需要什么环境、先运行哪份代码、输出在哪里、哪些内容不能分发。

文档 最少需要回答
来源清单 哪个提供方、哪次导出、哪些条件、哪些文件及指纹
字段字典 含义、类型、单位、缺失、口径、有效时期
处理协议 哪些操作允许，哪些必须等待人工决定
审计报告 样本量如何变化、键是否唯一、哪些异常未解决
决策记录 谁根据什么依据，在何时批准了哪条规则
运行说明 如何获取授权数据、执行、核对和交接

可以委托 Agent 生成这些文档的初稿，但字段含义须有来源，不能把它从列名猜出的解释写成事实。所有权不能靠控制人名称含几个关键词便自动二分，缺失单位不能靠数量级自动决定。

3.8 从小任务到可复用工作流

现在可以把全章连起来：先列来源和粒度，检查类型与键，明确聚合规则，再连接数据并保存审计，最后将经过核验的中间结果供下游重复使用。

任务：把年度财务与日行情形成年度分析底表。
输入：已列明来源与 schema 的年度表、日表、身份历史表。
目标：年度底表；保留原字段，单独增加指定的交易指标。
约束：原始数据只读，不猜单位，不自动去重或填补缺失。
步骤：检查键与期间，说明聚合公式，再合并并保留匹配标识。
验收：输入输出数量、双方键检查、匹配状态、分组未匹配率、
变量单位、支持期与信息日期检查；SQL/pandas 对照时比较结果。
停止条件：重复原因不清、身份有效期缺失、口径不一致。

读者可以 clone 仓库后运行 Notebook 第 04–05 节，观察真实财务表如何落实这些步骤。代码已经提供；学生的任务是能够解释为什么采取这些操作，以及现有证据还不足以支持什么。

本讲练习：给一张证券日表和一张公司年表各写出主键；指出同一个连接在年度描述与日度预测中的不同条件；说明 CSV、Parquet 和 SQLite 分别保存了哪些信息；为一次追加后的重复设计核查规则。下一讲进入清洗、变量构造和审计。
