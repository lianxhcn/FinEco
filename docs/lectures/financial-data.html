2  金融数据分析：流程、环境与数据获取

一位同学想研究企业负债与盈利能力的关系，下载了财务数据便开始回归。另一位同学先写下研究对象、时期、报表口径和信息日期，再决定下载哪些表。两人的区别从获取数据之前就开始了：数据容易获得，并不意味着它恰好回答我们的问题。

本讲从分析流程展开，介绍数据类型、工具分工和主要获取方式。《数据分析与经济决策》课程的流程、数据、工具与 AI和金融数据获取是本讲的主要基础；本课程将其接到金融计量研究和可审计的数据工作流上。

本讲要点

读完后，应能把研究问题写成数据需求，区分数据源与获取工具，解释一次数据分析中人、代码和 Agent 的职责，并保存可复现的输入快照。后续依次学习数据管理、清洗与审计，最后完成 CSMAR 实战。

2.1 数据分析的基本流程

数据分析通常从一个尚不清楚的问题开始，逐渐转化为可以用证据回答的问题。假设关心负债较高的企业是否盈利较差，我们至少要确定：比较哪些企业、看同年还是下一年的盈利、比较的是相关性还是负债变化的因果影响。最后一个区别将影响研究设计，不能等回归完成以后再决定。

图 2.1 的箭头给出工作顺序，虚线提醒我们实际工作会反复迭代。例如，发现某项指标只从 2018 年开始披露，可能需要调整研究时期，也可能需要换指标；这些都必须回到研究问题判断，不能只让代码填补前面的年份。

阶段 需要完成什么 在企业负债例子中要问什么 留下什么
问题定义 把宽泛主题转成具体问题 描述关系、预测盈利，还是识别因果作用？ 研究问题与目标总体
数据获取 按对象、期间、频率取得资料 是否保留退市企业？需要哪种报表？ 原始文件、来源与下载条件
管理和清洗 统一可确认的结构，诊断异常 一行是证券年度还是公司年度？ 字典、代码与样本流
探索性分析 看分布、趋势和组间差异 差异是否由行业或异常分母驱动？ 描述统计与诊断解释
建模分析 使模型对应研究目标 回归系数是否有因果含义？ 模型设定和可执行程序
解读与评价 解释数量级、误差与适用范围 统计差异是否具有经济意义？ 结论、替代解释与局限
报告与复现 让别人理解并检查分析 别人能从同批输入得到同样输出吗？ Notebook、环境与运行说明

描述、预测和因果分析可能使用相同字段，但验收目标不同。描述分析要说清楚样本覆盖；预测需要划分训练和测试时期，并限制信息集；因果分析还要论证识别假设。把一套准确率很高的预测代码改成回归输出，不能自动得到因果解释。

2.2 数据类型与结构

选工具之前，先判断拿到的对象是什么。一个 PDF 看起来有表格，但未必能直接作为数据框读取；六位证券代码由数字组成，也不意味着可以对它计算均值。

2.2.1 按结构化程度区分

结构化数据以明确行列存储，例如公司年度财务表，每行对应一个已定义的观测单位，每列含义和类型固定。半结构化数据带有键、标签或层级，例如 JSON、XML、HTML 和 XBRL；提取时需要保留层级关系。非结构化资料如公告文本、电话会议音频或图像，没有直接可用于回归的统一字段。

类型 金融例子 进入分析前的关键工作
结构化 股票日行情、年度财务表 检查键、类型、单位与时间
半结构化 API 的 JSON 响应、XBRL 财报 识别层级、提取字段、保留关联
非结构化 年报段落、公告扫描件、电话会议音频 转录或解析，再定义和验证测量规则

表格与文本可以共同提供信息。例如，资产负债表给出债务存量，附注解释债务期限和抵押条件。结合这些资料称为多模态分析的一种情形。它增加信息，也增加匹配和测量环节；模型提取的风险标签仍需验证，见文本变量的测量。

2.2.2 按时间维度与生成方式区分

截面数据比较一个时期的多个对象；时间序列跟踪一个对象的多个时期；面板数据同时含对象与时期。公司—年度是一种面板结构，但不同公司可能有不同覆盖年份。缺年份未必是漏读，也可能来自尚未上市、退市或制度变化。

观测数据来自实际经济活动；实验数据来自研究者安排的干预和分配。准实验描述的是依靠制度或外部变动建立识别的研究设计，不能因为文件被叫作准实验数据就免于论证外生性。面板结构也不自动消除混杂。数据形式告诉我们能怎样组织信息，研究设计决定可以作怎样的解释。

2.3 从 DGP 到研究数据

这一节解释一个容易混淆的问题：数据库中的一行记录与经济世界中的一家企业是什么关系？企业在经营中形成收入、成本、资产和负债，披露规则决定哪些活动被记录，数据库再按自己的字段和时间规则整理这些记录。研究者拿到的已经是经过多层选择与测量的结果。

数据生成过程 (data-generating process, DGP) 描述变量如何由经济环境、行为和随机因素形成。比如企业利润会受到产品需求、成本和经营决策影响。但利润发生之后，是否进入我们的 CSV，还取决于企业是否上市、是否披露、数据库是否覆盖，以及下载时选了哪些条件。

读 图 2.2 时，要分别问三个问题：谁有机会被记录？记录值测量了什么？研究者又选择了哪些记录？这些问题不能靠增加一条数据清洗命令解决。

假设研究对象是某年所有企业的盈利能力。非上市小企业可能没有进入上市公司数据库；经营困难的公司可能退市；下载界面若只选择当前上市公司，还会进一步排除曾经观察得到的公司。最终样本的均值可以计算得非常精确，却未必回答原来的总体问题。

用一个简单记号表达这个区别。令 \(S_{it}\) 表示企业 \(i\) 在年份 \(t\) 是否进入最终样本，进入为 1，否则为 0；\(Y_{it}\) 表示这一年的某个结果，如以比例表示的盈利能力。我们实际观察到的平均水平对应 \(E(Y_{it}\mid S_{it}=1)\)。总体平均水平是 \(E(Y_{it})\)。如果是否入样与盈利状况有关，两者一般不能直接画等号。

这里的期望表示相应总体中的平均水平，不是一个要求你立即估计的回归模型。它提醒我们：样本选择规则本身就在限定结论。仅凭样本量大，不能判断样本是否具有代表性。

将下载条件写进研究记录

保存数据库名称、导出时间、样本范围、起止期间、字段、频率及报表类型。下载时间未知时明确记为 unknown。文件的本次读取日期不能冒充最初下载日期。

2.4 环境与工具：每一层负责什么

面对 Python、Jupyter、Quarto、Git 和 Agent 等名称，初学者容易以为它们是互相替代的软件。实际上，它们承担不同工作。知道数据在哪里、代码由谁执行、结果由谁发布，比一次安装很多工具更重要。

2.4.1 语言、编辑器、内核与报告

本课程用 Stata 讲主要计量方法，用 Python 处理数据；R 也是统计研究中的常用语言。选择应依据已有工作流、方法实现与团队协作，不需要为了使用 Agent 放弃已经熟悉的软件。

层次 作用 本课程中的位置
Python / Stata / R 执行数据处理或估计命令 方法和数据任务使用对应语言
编辑器 编写与查看文件 可以使用熟悉的编辑器或 Codex 工作区
Jupyter Notebook 将说明、代码和输出放在同一文档 Python 实验的执行与展示载体
内核与环境 提供真正运行代码的解释器和依赖 决定导入哪个包、使用哪个版本
Quarto 将文档和已保存输出渲染为网页 课堂展示不实时取数、不执行代码
Git / GitHub 跟踪代码和文档版本、协作与分发 受限数据库不进入公共仓库

Notebook 显示了代码，不代表已经运行过；显示了输出，也不代表输出对应当前代码。修改单元后跳着运行可能留下隐藏状态，因此课前验证要重启内核并从头执行。安装包成功而 Notebook 仍提示找不到包时，应核对执行内核与安装时使用的解释器是否一致，不宜反复升级整个环境。

Python 中，pandas 负责表格操作，NumPy 提供数组计算，绘图库负责图形，统计或机器学习包负责模型。数据获取库处在上游，不能代替数据字典或质量检查。后面的 CSMAR 案例使用 pandas 与 Parquet，数据以本地授权快照为输入。

2.4.2 版本控制与复现

Git 帮助回答代码和规则在何时发生变化，数据 manifest 帮助识别当时使用哪一批输入。两者配合，才能区分结果变化来自数据更新、代码调整，还是研究规则改变。只保存一个名为“最终版”的 Excel 无法提供这些证据。

受限数据要在 Git 之外管理，保留文件指纹、访问说明和代码接口即可。把数据放入 Git LFS 仍属于分发，不能替代授权。环境的包版本也应记录；复现并不要求每次安装最新版本，而是先恢复经过验证的组合。

2.4.3 从对话建议到 Agent 执行

可以把一次 Agent 工作理解为读取资料、制定步骤、调用工具、观察结果并调整。是否能读写文件或运行代码，取决于具体环境和授权，不能仅凭产品名称判断。学生要检查它实际做了什么，而非只看最后一段总结。

分析环节 可以委托的工作 学生须判断的内容
问题与资料 整理候选数据需求、查找文档 需求是否对应研究问题，来源是否可靠
获取与读取 编写读取代码、记录参数和来源 授权、样本条件和字段定义
管理与清洗 检查键、转换已确认类型、生成审计 何时允许删除、填补或重新编码
模型与报告 编码、排错、整理输出与文字 识别假设、推断、数量级和结论边界

目标对齐是很实际的问题：我们想知道补贴是否促进研发，却只要求 Agent 回归研发对补贴，它可能完成回归而没有回答因果问题。任务中应同时写研究目的、允许操作和验收证据。AI 摘要与方案适合初筛，重要学术判断仍须精读和独立核验。

2.5 数据在哪里？

在开始写代码之前，先花一点时间弄清楚：做金融分析，数据到底从哪来？本节迁入《数据分析与经济决策》数据在哪里的分类和资源表；保留主要内容，并更新授权与工具边界。

2.5.1 金融数据的现实格局

机构中的研究工作经常通过商业数据库获取金融资料，例如 Wind、Bloomberg 和 CSMAR。它们整理不同市场与主题的数据，提供查询或导出功能。能访问哪些产品、历史区间和接口，取决于订阅与授权，不能从数据库名称推断学校已购买全部内容。

在校学习应先查看学校图书馆的数据库入口和课程分发说明。CSMAR 是本单元上市公司案例的来源，教师提供的是特定导出批次。学生不需要把账号交给 Agent；拿到授权文件后，仍要检查导出条件、字段说明和期间。

公开机构数据与开源接口提供了另外的入口。它们适合学习和许多研究任务，但能否使用取决于具体数据定义、覆盖和许可。软件开源、下载不收费、无需注册、可以再分发，是四个不同条件。

2.5.2 四类数据来源

商业数据库。 Wind、Bloomberg、CSMAR 等已完成大量收集、匹配和整理工作。优点是有相对系统的主题划分与文档；研究者仍需核对字段、历史版本和授权。相同名称的指标可能来自不同计算口径，不能默认数值一致。

开源 Python 数据接口。 AKShare、yfinance 等将某些数据访问过程封装为函数。调用方便，但这些包通常不是数据的最初生产者；上游字段、网站或权限变化会影响接口。保存包版本之外，还应记录实际上游来源与请求参数。

官方机构及其接口。 世界银行、FRED、国家统计局等是宏观研究的重要入口。定义和修订说明同样重要：当前下载的历史序列可能与当年公布值不同，名义与实际值、季调与未季调值不能混用。

数据平台和学术档案。 Kaggle、Harvard Dataverse、ICPSR 等提供数据集、代码和项目说明。它们有助于学习完整分析，但不同项目的许可和可得范围不同；有的只提供代码，有的提供部分公开数据，不能把平台中的全部资料当作可直接再发布的数据。

下面按查找任务整理入口。表格用于定位资料，不作质量排名；访问权限与产品范围以当前官方说明为准。链接核验日期为 2026-09-16。

论文复现资料可以让我们看到领域中怎样定义变量、连接数据和筛选样本。不要只下载一张整理好的最终表，还应读 README 和生成脚本。能否再做延伸分析，取决于许可、原始输入是否可得以及数据是否适合新问题。本单元在复现包阅读中展示具体方法。

2.6 从文件与 API 取得可检查的数据

本节将来源讲义第 9.2–9.4 节合并。核心操作是找到数据、读入、看清结构并保存快照；学生应能说明每一步的目的，不必背下全部接口函数。

2.6.1 本地文件：先检查路径、编码和类型

CSMAR 导出、统计年鉴和学术数据经常先以文件形式落到硬盘。CSV 是通用文本表，XLSX 支持多工作表和人工展示，DTA 保存 Stata 类型与标签，Parquet 适合重复读取分析数据。文件格式各有用途，原始文件按下载形式保存，转换到另一种格式时另存派生文件。

输入 pandas 常见读取入口 第一次读入尤其要检查
CSV read_csv 编码、分隔符、证券代码、缺失标记
Excel read_excel 工作表、表头位置、脚注和合并单元格
Stata read_stata 标签、类别、日期和扩展缺失值转换
Parquet read_parquet schema、读取列及当前数据版本

证券代码应保留字符串，例如 000001。若读取时已变成整数 1，再补零需要确认编码规则，不能对任何标识符一律补六位。日期转换也应统计失败值，不能用一个随意日期替代。完整的离线读取、合并和存储例子见 Notebook 的教学小表，不需要现场调用 API。

读入后按顺序检查 shape、小范围内容、类型与非缺失数量、描述统计。行列数回答有没有明显漏读；小范围内容帮助判断表头和单位行；类型检查发现字符与数值混淆；分布检查发现异常量级。处理受限资料时，公开 Notebook 只显示汇总，原始行在授权本地查看。

遇到 FileNotFoundError，先确认工作目录和相对路径；遇到中文乱码，依据文件说明确定编码；遇到数值列含 --，先判断它是否确实表示缺失。反复更换读取参数直至不报错，不能替代这些核对。

2.6.2 在线文件与 API：入口、参数和响应

在线下载应区分网页地址与文件地址。GitHub 的普通文件页是 HTML 展示，Raw 链接才返回文件内容；URL 可访问也不保证响应就是所需 CSV。稳健的下载流程检查状态、响应类型和内容，再保存原始字节、时间与校验值。遇到登录页或拒绝访问，不将 HTML 错当数据，也不通过伪装绕过权限。

API 即应用程序编程接口。可以沿用来源讲义的点餐类比：端点相当于菜单入口，参数相当于菜品和口味，认证说明是否有访问权限，响应是返回的结果。但 API 不保证免费、实时或无误；有的需要分页，有的每次最多返回一定数量的记录。

  1. Step 1: 根据官方文档明确端点或函数、参数、频率、单位与权限。
  2. Step 2: 先请求很小的时间范围，核对字段、数量和日期。
  3. Step 3: 按文档处理分页、超时和访问频率限制，记录失败批次，不把失败当零条数据。
  4. Step 4: 保存输入快照、请求参数、版本和下载日期，后续分析读取该快照。

密钥若为接口所需，应由用户在环境中自行配置，不能放进提示词、Notebook 输出或 Git。持续更新任务与课堂复现任务分开：前者更新快照，后者使用已检查版本。

2.6.3 AKShare：以历史行情理解参数

AKShare 把部分数据访问封装成 Python 函数。股票接口官方文档提供历史行情接口 stock_zh_a_hist 的说明。先理解参数再调用：symbol 选择证券，period 选择频率，start_date 与 end_date 限定期间，adjust 指定价格调整方式。实时行情快照与历史序列回答不同问题，不能用今天的股票名单代表过去的可投资集合。

参数或选择 读者必须说明
股票与日期范围 选择是否依赖事后表现；边界是否包含所需支持期
日、周、月频率 使用交易频率还是财务报告频率
不复权、前复权、后复权 价格调整依据与研究用途
成交量、金额、涨跌幅 原始单位以及百分数与小数的区别

复权处理除权除息等公司行为造成的机械价格变化。一个仅有现金分红的教学例子：前日价格 10 元，除息后价格 9 元，同时每股得到 1 元现金。忽略税费，含分红回报为 (9+1)/10-1=0，只看价格变化则为 −10%。这说明需要明确回报定义，不意味着某个复权选项在所有任务中都自动正确。

前复权和后复权选择不同的价格标度；调整因子、现金分红处理和未来更新规则仍应核对。不要把后复权价当作当时可成交价格，也不能仅凭保存了复权历史就宣称消除了前视偏误。来源讲义中的实时接口代码可作为查询入口，本书课堂展示使用冻结快照，不声称本轮重新测试了所有实时端点。

2.6.4 写给 Agent 的获取任务

完整任务应说明想拿什么及如何验收。下面是可调整的模板；研究范围由学生填写，不能让 Agent 代选表现最好的股票。

目标：为已明确的研究对象和期间获取数据，供后续离线分析。
先阅读官方字段与接口文档，列出来源、参数、频率、单位、
权限、分页和可能的修订规则，供我核对。
只在指定项目目录工作；不读取账号或密钥；不覆盖已有快照。
先用短期间检查字段和日期；不得把请求失败记为零观测。
成功后保存原始响应或导出文件、来源 URL、下载时间、请求
参数、软件版本、SHA256 和失败清单。输出覆盖与缺失汇总。
数据定义或授权不清时停止相应步骤并列出待确认事项。

这段任务不以一个漂亮图形作为获取成功的唯一证据。下载文件、字段说明和来源记录齐备，下一章才有条件讨论怎样管理和连接。
