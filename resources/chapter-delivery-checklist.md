# 章节交付检查表

配合 [交接标准](chapter-handoff-standard.md) 使用。勾选表示检查完成；阶段通过仍须满足下方条件，不能用已记录 `pending` 代替资产可用。

## 1. 资产接收

- [ ] 当前稿件、`ASSET_MANIFEST.md`、`HANDOFF.md` 存在且版本对应。
- [ ] 教师决定附确认日期与依据；未确认内容单列为建议。
- [ ] 正文图片、代码、Notebook、数据和文献依赖逐项列入清单。
- [ ] 新增资产实际随包交付；复用资产的路径、版本或链接可核验。
- [ ] 受限资产注明合法获取方式与接收端可用状态，没有复制受限材料或凭据。
- [ ] `pending` 项已列明影响与下一步；`N/A` 项有理由且无未交付的本地依赖。
- [ ] ZIP 已重新打开核对实际文件；非 ZIP 交付已核对目录文件清单。

资产阶段：`PASS / NOT READY`。关键资产不可用或关键项为 `pending` 时填写 `NOT READY`。

## 2. 本章执行与交接

- [ ] 已读取当前规则、`repo-plan.yml` 与章级任务，核对 Git 状态和文件所有权。
- [ ] 上游两份记录按版本保留在 `logs/<topic>/upstream/<package-version>/`，没有覆盖历史记录。
- [ ] 稿件与资产按授权范围映射，保留数据来源、口径、日期及模拟标记。
- [ ] 需执行的 Notebook 或脚本已按规则从头运行，真实输出对应当前代码和数据。
- [ ] 本章隔离预览按权限完成；公共导航、样式、依赖、作业编号及主目录 `docs/` 未被章节窗口修改。
- [ ] `logs/<topic>/handoff.md` 包含文件映射、环境、命令、结果、缺口和公共变更请求，跨 worktree 证据已移交。

执行阶段：`PASS / NOT READY / N/A`。选择 `N/A` 须说明本章无执行代码；预览结果另行记录，不能替代执行证据。

## 3. 整合窗口验收

- [ ] 已核对本章执行证据与资产完整性，适用的前序阶段均通过。
- [ ] 已按权限处理公共接入与全书构建，渲染未执行代码或实时取数。
- [ ] 图片、公式、表格、编号、链接及返回入口检查完成。
- [ ] 公开范围检查完成，日志、受限资料和教师答案未进入网站输出。
- [ ] 页面检查结果、剩余非阻塞待办及其影响已写入本地交接记录。

页面阶段：`PASS / NOT READY`。适用阶段均通过后才能记录工程整合完成；提交、推送和发布按已有授权另行记录，不由本检查表授予权限。
