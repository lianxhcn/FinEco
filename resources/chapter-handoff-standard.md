# 章节交接标准

## 1. 适用范围与规则入口

用于网页 ChatGPT 向本地 Codex 交接章节稿件及教学资产。上游 Markdown 是稿件；本地理论与执行文件仍按项目规则落为 `.qmd` 和 `.ipynb`。

接收前读取当前 `AGENTS.md`、`RULES.md`、`PROJECT_PLAN.md`、`README.md`、`_quarto.yml`、`repo-plan.yml` 及本章任务。本文不扩大章级文件权限；规则或教师决定发生冲突时记录位置并报告。

## 2. 交接包与依赖

至少提供当前稿件、`ASSET_MANIFEST.md`、`HANDOFF.md`。使用 [资产清单模板](ASSET_MANIFEST-template.md) 逐项列出正文依赖，不能只列目录。

- 新增图片、代码、Notebook、可分发数据等随包交付。已确认但漏交的资产应补交，不由下游根据描述重造。
- 复用仓库资产时记录仓库相对路径及 commit；未提交资产可记录文件校验值和快照日期。已上传图片记录准确图床链接及核验日期，沿用现有 PicGo 规则。
- 受限数据或资料记录来源、授权获取方式及接收端可用状态，不附凭据，不为满足交接要求复制受限全文或数据。关键依赖尚不可用时保留待补齐状态。
- 文献可作为稿件中的完整参考文献及可核验链接交付，不强制复制论文 PDF。不需要独立目录的资产类型标记 `N/A` 并说明理由；仍存在的外部引用另行记录。
- 以 ZIP 交付时，生成后重新打开并核对清单、关键文件及空目录；普通目录交接直接核对文件清单。

`HANDOFF.md` 记录主题、包版本、稿件版本、教师确认的教学决定及确认日期和依据、未确认建议、待办和下游接口。不因上游写有已确认就省略确认依据。

## 3. 本地接收与记录

1. **Step 1**: 核对本章所有权、Git 状态及上游清单和交接说明，逐项对照正文引用与实际资产。
2. **Step 2**: 在 `logs/<topic>/upstream/<package-version>/` 保留原始 `HANDOFF.md` 与 `ASSET_MANIFEST.md`；原记录只读，同版本有不同内容时报告冲突，不能覆盖。新版本另存。资产按本章授权目录落位，映射写入本地交接记录。
3. **Step 3**: 关键资产缺失或不可用时将资产状态记为 `NOT READY`，在 `logs/<topic>/handoff.md` 写明缺口、影响、补齐方式；可继续独立的静态审阅或其他已授权工作。
4. **Step 4**: 章节窗口验证本章代码与真实输出，按权限做隔离预览，提出公共变更请求；不得修改共享导航、依赖或主目录 `docs/`。
5. **Step 5**: 整合窗口接收资产及本地证据后处理公共接入、全书构建与页面检查。是否提交、推送、发布仍按当前任务授权和已有 Git 规则执行。

上游记录说明教学决定与交付资产，本地 `logs/<topic>/handoff.md` 说明映射、环境、执行命令、输出、检查结果和公共变更请求。两种记录都不发布；跨 worktree 需移交，不能假定 Git 自动同步被忽略的日志。

## 4. 分阶段验收

| 阶段 | 通过条件 | 责任窗口 |
|---|---|---|
| 资产就绪 (`asset-package-ready`) | 稿件、清单、交接说明齐全，关键依赖实际可用且引用可核验 | 上游提供，接收窗口核对 |
| 执行验证 | 需执行的代码已按规则从头运行并保存真实输出，证据对应当前代码与数据 | 章节窗口 |
| 页面验收 | 公共接入、构建及图片、公式、表格和链接检查完成 | 整合窗口 |

每阶段分别标记 `PASS`、`NOT READY` 或有理由的 `N/A`。关键依赖存在 `pending` 时相应阶段不能通过；静态审阅完成或渲染成功不能替代执行验证。无执行代码时可将执行阶段记为 `N/A`。只有适用阶段均通过，才标记工程整合完成；发布状态另外记录。具体检查见 [交付检查表](chapter-delivery-checklist.md)。
